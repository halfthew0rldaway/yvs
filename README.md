### Alur Operasional Sistem (End-to-End Operational Lifecycle)
```mermaid
flowchart TD
    A[Customer Datang Membawa Unit] --> B{Customer Terdaftar?};
    B -- Belum --> C[Registrasi Customer & Profil Kepribadian Komunikasi];
    B -- Sudah --> D[Registrasi / Pilih Perangkat];
    C --> D;
    
    D --> E[SOP Intake: Checklist Fisik 15 Poin, Defect Map 2D & Izin Privasi];
    E --> F[Penerbitan Tiket Servis, Pemilihan SLA Reguler/Express & Token Tracking];
    
    F --> G[Teknisi Menerima / Ambil Alih Tiket & Diagnosis Hardware];
    G --> H{Butuh Penggantian Suku Cadang?};
    H -- Ya --> I[Teknisi Input Estimasi & Suku Cadang Diperlukan];
    I --> J[Kirim Proposal Estimasi Biaya ke WhatsApp Customer];
    J -- Disetujui --> K[Mulai Pengerjaan & Potong Stok Sparepart Otomatis];
    J -- Ditolak --> Batal[Tiket Dibatalkan & Unit Dikembalikan Utuh];
    H -- Tidak --> K;
    
    K --> L[Update Log Perbaikan Berkala & Dokumentasi Foto];
    L --> M[Inspeksi Kualitas WOW Quality Control 8 Poin];
    M --> N{Lolos QC 8 Poin?};
    N -- Belum --> K;
    N -- Lolos --> O[Tiket Status: Selesai di Rak Penyimpanan];
    
    O --> P{Customer Langsung Ambil?};
    P -- Ya --> Q[Admin Cetak Faktur Invoice Resmi];
    P -- Belum (>14 Hari) --> Unclaimed[CRM: Monitoring Rak Unclaimed & Pengingat Bertahap WA];
    Unclaimed --> Q;
    
    Q --> R[Serah Terima Unit, Tips Perawatan Mandiri & Aktivasi Garansi];
    
    R --> S[CRM: Monitoring Garansi H-7 & Follow-Up Kepuasan Pelanggan];
    S --> T{Ada Kendala Masa Garansi?};
    T -- Ada --> Claim[Penerbitan Tiket Klaim Garansi Berantai - Parent Child];
    Claim --> K;
    T -- Aman --> U[Siklus CRM: Perawatan Berkala Rutin 6-12 Bulan & > 1 Tahun];
    U --> V[Pengiriman Pengingat Servis Berkala Sesuai Tipe Kepribadian];
    V --> A;
```

### Alur Penggunaan Aplikasi di Web (Web Flow)

Selain dari proses bisnis operasional, berikut adalah bagaimana fitur di dalam web Serv.io digunakan secara aktual oleh Admin dan Teknisi. 

#### Pembagian Tanggung Jawab:
- **Admin**: Menangani area _front-desk_ dan manajerial. Admin bertugas menambahkan Master Data (Customer, Perangkat, Sparepart, Akun User), membuat Tiket Servis baru ketika ada pelanggan, menugaskan tiket ke teknisi tertentu (bisa manual), serta mengurus penagihan (Invoice) di akhir servis.
- **Teknisi**: Menangani area operasional _back-end_ perbaikan. Teknisi bisa melihat daftar antrean servis, mendiagnosis masalah, menambahkan catatan perbaikan (_Log_), dan mencatat _sparepart_ apa saja yang digunakan selama perbaikan berlangsung.

#### Fitur Ambil Alih Tiket (Self-Assign vs Admin Assign)
Dalam web Serv.io, proses delegasi servis ke Teknisi sangat fleksibel:
1. **Admin Assign (Ditunjuk Admin)**: Saat membuat tiket servis baru atau mengedit tiket yang ada, Admin bisa langsung memilih _dropdown_ nama Teknisi yang akan menangani.
2. **Ambil Alih Tiket (Self-Assign)**: Jika Admin mengosongkan teknisi pada tiket tersebut (Status: Diterima), maka Teknisi yang sedang login dan melihat ada "Tiket Kosong" dapat langsung menekan tombol **Ambil Alih**. Ini mempercepat proses tanpa perlu menunggu arahan dari Admin.

```mermaid
flowchart TD
    Start((Mulai)) --> Login[Login ke Sistem]
    Login --> Role{Role User?}
    
    %% Alur Admin
    Role -- Admin --> AdminMenu[Dashboard Admin]
    AdminMenu -->|Kelola Data| MasterData[Input Customer dan Perangkat]
    AdminMenu -->|Penerimaan| BuatTiket[Membuat Tiket Servis Baru]
    BuatTiket --> Assign{Admin Pilih Teknisi?}
    Assign -- Ya --> TungguProses[Tiket Ditugaskan ke Teknisi A]

    %% Alur Teknisi

    TeknisiMenu --> CekTiket{Cari Tiket Baru?}

    AdminInvoice --> Selesai((Selesai))
```

## Fitur Unggulan & Kapabilitas Sistem

Platform Serv.io dirancang dengan standar operasional bengkel IT profesional berskala enterprise, menggabungkan efisiensi manajemen teknis, standar operating procedure (SOP) yang ketat, dan retensi pelanggan berbasis data psikologis komunikasi.

### 1. Modul Retensi & CRM Pelanggan Terpadu (`/retensi`)
Modul terdedikasi untuk menjaga hubungan jangka panjang dengan pelanggan dan mengoptimalkan siklus servis berulang (customer lifecycle):
* **Siklus Perawatan Berkala (Periodic Maintenance Recall)**:
  - Mendeteksi otomatis perangkat yang telah selesai dan diambil $\ge 6$ bulan (180 hari) hingga $\ge 1$ tahun.
  - Pengelompokan cerdas: **Siklus Rutin (6-11 Bulan)** vs **Siklus Mendesak / Kritis ($\ge 1$ Tahun)**.
  - Rekomendasi tindakan servis otomatis disesuaikan dengan kategori perbaikan sebelumnya (*Deep clean & repaste pasta termal pendingin*, *Pemeriksaan S.M.A.R.T SSD / Storage*, *Pelumasan dan pengencangan baut engsel bodi*).
  - Tombol **`Recall (X bln)`** terintegrasi langsung pada tabel riwayat servis di profil pelanggan (`CustomerDetailModal`).
* **Monitoring Unit Belum Diambil (Unclaimed Aging Devices)**:
  - Memantau unit yang telah selesai diperbaiki namun belum diambil pelanggan di rak penyimpanan bengkel.
  - Klasifikasi penumpukan 5 tingkat: **Siap Diambil** ($< 14$ hari), **Menumpuk di Rak** ($\ge 14$ hari), **Perhatian** ($\ge 30$ hari / 1 bulan), **Peringatan** ($\ge 60$ hari / 2 bulan), dan **Kritis Penyimpanan Bengkel** ($\ge 90$ hari / 3+ bulan).
  - Fitur eskalasi pengingat bertahap (*Reminder Tahap 1, 2, dan 3*) via WhatsApp dengan pencatatan otomatis ke log perbaikan dan jejak audit.
* **Evaluasi & Proteksi Garansi (H-7 Expiring Warranties)**:
  - Pelacakan real-time untuk seluruh tiket servis bergaransi aktif yang akan berakhir dalam rentang **H-1 hingga H-7**.
  - Memungkinkan staf/service advisor proaktif menghubungi pelanggan guna memastikan performa unit memuaskan sebelum masa garansi kedaluwarsa.
* **Generator Pesan WhatsApp Cerdas Berbasis 5 Tipe Kepribadian Psikologis**:
  - Personalisasi bahasa secara otomatis menyesuaikan profil kepribadian pelanggan:
    - **Koleris**: Nada tegas, ringkas, *to the point*, kepastian estimasi waktu pengerjaan dan transparansi biaya.
    - **Sanguinis**: Nada ceria, hangat, bersahabat, apresiatif, menyertakan salam antusias.
    - **Melankolis**: Nada terstruktur, formal, rinci, menyertakan catatan garansi tertulis dan spesifikasi teknis part.
    - **Plegmatis**: Nada santai, ramah, menenangkan, tidak terburu-buru, mengutamakan keawetan perangkat jangka panjang.
    - **Netral**: Standar komunikasi komersil dan profesional untuk kebutuhan bisnis/kantor.
  - Dilengkapi opsi toggle diskon perawatan berkala, catatan teknisi kustom, tombol salin ke clipboard, dan tombol langsung ke WhatsApp Web / Desktop (`wa.me`).
* **Widget Asisten Interaktif 3D Floating CRM (`ServiBot3D`)**:
  - **Pure 3D Floating Mascot**: Maskot robot asisten 3D berestetika *pearl-white ceramic* dengan visor kaca melengkung dan mata *glowing azure* yang melayang bebas secara global di seluruh halaman aplikasi (`Layout.jsx`) tanpa box kontainer kaku.
  - **Fisika Levitasi & Draggable**: Dapat digeser bebas (*drag & drop*) ke sudut layar mana pun dengan animasi levitasi mengambang yang halus dan responsif saat kursor diarahkan (*hover micro-interaction*).
  - **Balon Sapaan Interaktif (Teaser Bubble)**: Menampilkan status cepat dengan titik status berkedip (*"X unit siap servis berkala"*, *"X unit kritis butuh recall!"*, atau *"Semua unit aman optimal"*) berdampingan dengan badge notifikasi unit.
  - **Drawer Popover Berbasis Komponen Visual (Tanpa Teks Menumpuk)**:
    - *Visual Split Ratio Bar*: Bar rasio dinamis dua warna yang memvisualisasikan proporsi unit Rutin (Biru) vs Kritis (Merah).
    - *Metric Chips*: Kartu metrik cepat 6–12 Bulan dan &gt; 1 Tahun Kritis dengan ikon representatif.
    - *Antrean Prioritas Cepat*: Daftar ringkas 3 unit teratas dengan ikon perangkat, nama pelanggan, badge durasi, dan tombol 1-klik kirim WhatsApp resmi tanpa emoji.
    - *Direct CTA*: Tombol utama untuk langsung membuka modul CRM Retensi penuh atau membuka modal penjadwalan recall interaktif.

### 2. Standar SOP Penerimaan (Intake) & Proteksi Keamanan Privasi Pelanggan
* **Checklist Inspeksi Fisik Masuk (15 Poin Standar Industri)**:
  - Pengecekan menyeluruh saat unit diserahkan: *touchpad, keyboard, baterai, port USB, sound speaker, audio jack, WiFi / LAN, webcam, kebersihan fisik, status sistem operasi, lisensi, dan instruksi khusus pelanggan*.
* **Visual Interactive Defect Map (Pemetaan Cacat Fisik 2D)**:
  - Kanvas 2D visual interaktif untuk mencatat titik cacat fisik (*scratch, dent, crack, stain*) pada 4 bidang bodi (cover atas, panel layar, keyboard/palmrest, dan casing bawah).
* **Device Credential Vault (Penyimpanan Sandi Teknis)**:
  - Penyimpanan aman jenis pengunci perangkat (*PIN, Password, Pola Kunci, atau Tidak Ada Kunci*) untuk kebutuhan pengujian teknisi tanpa membocorkan privasi pelanggan, dilengkapi tombol reveal/hide sandi.
* **Kuasa Hukum & Batasan Privasi Pelanggan**:
  - Pencatatan persetujuan resmi: *Izin bongkar unit*, *Izin akses sistem operasi*, *Izin backup data mandiri*, serta catatan *Batasan Izin* (misal: "Dilarang membuka partisi dokumen pribadi D:").
* **Dual-Phase Dynamic SLA Engine (Pengecekan vs Pengerjaan Servis Fisik)**:
  - **Pemisahan Tegas 2 Fase Waktu Operasional Bengkel**:
    1. **Tahap 1 - SLA Pengecekan & Diagnosis**: Waktu sejak unit diterima hingga tim teknisi merumuskan hasil diagnosa serta estimasi rincian biaya penawaran. (Express: 4 jam | Reguler: 24 jam | Kompleks: 48 jam).
    2. **Fase Antara - Menunggu Konfirmasi Pelanggan (Idle / Pause Status)**: Pengerjaan servis fisik bersifat mutlak dependen terhadap persetujuan (*ACC*) pelanggan. Selama tiket berada di status `menunggu_persetujuan`, timer SLA pengerjaan **di-pause** dan bengkel berada pada status *idle*, sehingga bengkel **tidak dikenakan penalti keterlambatan (overdue)** saat menunggu keputusan pelanggan.
    3. **Tahap 2 - SLA Pengerjaan Servis Fisik**: Waktu pengerjaan fisik baru dimulai *secara otomatis* sejak tanggal dan jam pelanggan menyetujui penawaran (`disetujui_at`). (Express: 6 jam | Reguler: 48 jam / 2 hari kerja | Kompleks: 96 jam / 4 hari kerja).
  - **Visualisasi Dual Stepper & Monitoring**:
    - Kartu hitung mundur dual-phase di halaman detail tiket dan pelacakan publik customer dengan status independen untuk masing-masing fase.
    - Filter cepat di daftar tiket: *Express Queue* dan *Overdue SLA* (mengisolasi pengecekan/pengerjaan yang benar-benar terlambat tanpa mencampuradukkan tahap menunggu persetujuan pelanggan).

### 3. Arsitektur Antarmuka Tiket Servis Ergonomis (Clean & Neat Collapsible UI)
* **Modular Accordion Architecture**:
  - Mengatasi kepadatan visual dengan menyembunyikan informasi sekunder secara *default* (Rekam Medis Unit Terdahulu, SOP Checklist Intake 15 Poin, Visual Defect Map 2D, dan Kredensial Perangkat) ke dalam panel collapsible yang rapi dan dapat dibuka hanya dengan satu klik.
* **Tampilan Bersih & Konsisten**:
  - Desain modern bernuansa *Slate / White*, tipografi tegas, bebas elemen dekoratif berlebih (*no AI slop*), serta konsisten menggunakan icon SVG solid (*Lucide React*) tanpa emoji.

### 4. Standar Inspeksi WOW Quality Control (8 Poin Handover)
* **Verifikasi Kualitas Sebelum Unit Ditandai Selesai**:
  - Meliputi 8 poin pengetesan krusial: *Power test kestabilan arus*, *Display test warna dan dead pixel*, *Keyboard & touchpad response*, *Audio multimedia*, *Port I/O connectivity*, *OS thermal stress test*, *Pembersihan fisik WOW bodi bebas debu*, dan *Kelengkapan aksesoris serah terima*.
* **Tips Edukasi Perawatan Mandiri (Post-Service Care Tips)**:
  - Catatan edukasi teknis dari teknisi spesialis (misal: tips menjaga sirkulasi udara laptop gaming, pemakaian charger original) yang otomatis tercantum pada faktur cetak dan halaman pelacakan publik pelanggan.
* **Pelacak Masa Garansi Digital Real-time**:
  - Sinkronisasi masa garansi otomatis berdasarkan tanggal unit diambil oleh pelanggan.

### 5. Klaim Garansi Berantai (Linked Parent-Child Warranty Claims)
* Penerbitan tiket servis klaim garansi yang secara resmi terhubung langsung ke ID tiket induk terdahulu (*Parent-Child Relationship*).
* Menjaga integritas data perbaikan berulang tanpa harus menginput ulang data perangkat maupun master customer.

### 6. Rekam Medis Perangkat Multi-Servis (Device Medical History Timeline)
* Riwayat perbaikan komprehensif lintas waktu berdasarkan nomor seri (*Serial Number*) perangkat.
* Memungkinkan teknisi mengetahui riwayat penggantian suku cadang sebelumnya, masalah berulang, kronologi servis masa lalu, dan akumulasi biaya perawatan unit.

### 7. Manajemen Logistik, Inventaris Suku Cadang & Harga Pokok (HPP)
* **Manajemen HPP Modal & Margin Penjualan**:
  - Setiap suku cadang mencatat harga beli modal (HPP) dan harga jual resmi untuk mendukung akurasi perhitungan laba kotor.
* **Indikator Early Warning Stok**:
  - Filter cepat untuk mendeteksi suku cadang dengan status *Stok Menipis* ($\le 2$ unit) dan *Stok Habis* ($0$ unit).
* **Log Pengadaan & Restok Suku Cadang dari Supplier**:
  - Dokumentasi transaksi restok lengkap dengan nama supplier, nomor faktur distributor, kuantitas masuk, tanggal beli, dan pencatat transaksi.
* **Harmonisasi Navigasi Logistik**:
  - Penataan tombol aksi header (*Log Pengadaan & Restok*, *Daftar Belanja Supplier*, dan *+ Tambah Sparepart*) dengan hierarki visual yang seimbang dan profesional.

### 8. Pustaka Pengetahuan Perbaikan Internal (Internal Repair Wiki)
* Basis pengetahuan teknis terpadu bagi tim teknisi:
  - Panduan penanganan kerusakan per merek (*ASUS, Lenovo, Apple, Dell, Acer, HP, MSI, Epson, Canon*).
  - Klasifikasi gejala kerusakan, analisa penyebab utama, langkah perbaikan terstruktur, komponen suku cadang terkait, tingkat kesulitan (*Mudah, Menengah, Mahir, Spesialis*), estimasi waktu, dan persentase tingkat keberhasilan.

### 9. Jejak Audit Aktivitas Pengguna (`ActivityLog`)
* Pencatatan riwayat aktivitas pengguna secara otomatis (*Auth, TiketServis, Diagnosis, LogPerbaikan, Sparepart, RestockLog, ChecklistQC, Invoice, RetensiCRM*) guna menjaga akuntabilitas dan jejak rekam operasional bengkel.

### 10. Portal Pelacakan Publik Transparan (`/tracking`)
* Akses pelacakan progres perbaikan mandiri bagi pelanggan tanpa perlu login.
* Menampilkan status pengerjaan, foto dokumentasi pengerjaan teknisi, rincian biaya estimasi, tips perawatan mandiri, dan status garansi unit.

### 11. Dashboard Analitik Operasional & Keuangan
* Menampilkan KPI bengkel: tiket aktif, unit selesai menunggu diambil, pendapatan biaya jasa, penjualan suku cadang, tren servis 6 bulan terakhir, performa teknisi, dan antrean servis mendesak.
* **Monitoring Kepatuhan SLA & Donut Chart Interaktif**:
  - Donut chart visual untuk distribusi tiket aktif berdasarkan kepatuhan estimasi (*Sesuai Estimasi / On Track*, *Mendekati Batas / Warning <12 Jam*, *Melewati Estimasi / Overdue*, dan *Menunggu Persetujuan / Pause ACC*).
  - Filter interaktif 1-klik dari segmen chart maupun kartu ringkasan langsung menuju antrean tiket terkait.
* **Manajemen Pencadangan Basis Data Mandiri (Database Backup)**:
  - Tombol pencadangan diposisikan secara ergonomis pada header *Log Aktivitas Terbaru* guna menjaga kerapian visual header utama.
  - Mendukung ekspor instan seluruh relasi database ke format **JSON** dan **Excel (.xlsx multi-sheet terstruktur)** dengan menu popover pintar yang membuka ke atas.

### 12. Buku Saku SOP Layanan Prima & Sertifikat Garansi Digital
* **Buku Saku SOP In-App (`SopModal`)**:
  - Panduan praktis terintegrasi langsung di navbar web mencakup *Service Excellent YVS* (Motto & Sikap Dasar, Pendekatan 4 Tipe Kepribadian, Standar Komunikasi Pesan WhatsApp, dan SOP Teknis Serah Terima).
* **Sertifikat Garansi Digital & Verifikasi QR Code (`WarrantyCertificateModal`)**:
  - Penerbitan sertifikat garansi digital resmi berstandar profesional yang memuat data nomor tiket, nama pemilik, spesifikasi unit, tanggal berakhir garansi, serta QR Code pelacakan publik instan.

## Panduan Instalasi dan Menjalankan Aplikasi

Panduan ini ditulis sedetail mungkin agar pemula sekalipun bisa menjalankan proyek ini. Ikuti langkah-langkah di bawah sesuai sistem operasi yang kamu gunakan.

### Prasyarat - Software yang Harus Diinstall Terlebih Dahulu

Sebelum memulai, pastikan software berikut sudah terpasang di komputer kamu:

| Software | Kegunaan | Link Download |
| :--- | :--- | :--- |
| **Node.js** (v18 ke atas) | Runtime JavaScript untuk menjalankan backend dan frontend | [nodejs.org](https://nodejs.org/) — Pilih versi **LTS** |
| **XAMPP** | Menyediakan server MySQL secara mudah (khusus Windows) | [apachefriends.org](https://www.apachefriends.org/) |
| **Git** | Untuk meng-clone repository ini | [git-scm.com](https://git-scm.com/) |

> **Cara cek apakah Node.js sudah terinstall:** Buka Terminal / Command Prompt, lalu ketik:
> ```
> node -v
> ```
> Jika muncul versi (contoh: `v18.17.0`), berarti sudah siap.

### Langkah 2: Nyalakan Server MySQL

<details>
<summary><h4>🪟 Windows - Menggunakan XAMPP</h4></summary>

1. Buka aplikasi **XAMPP Control Panel**.
2. Klik tombol **Start** pada baris **MySQL**.
3. Tunggu hingga statusnya berubah menjadi hijau (artinya MySQL sudah berjalan di port `3306`).
4. Buka browser, akses **http://localhost/phpmyadmin**.
5. Di phpMyAdmin, klik tab **"Databases"** di bagian atas.
6. Pada kolom **"Create database"**, ketik: `repair_workshop`
7. Klik tombol **Create**.

</details>

<details>
<summary><h4>🐧 Linux</h4></summary>

1. Buka Terminal.
2. Jalankan perintah berikut untuk menyalakan MySQL/MariaDB:
   ```bash
   sudo systemctl start mariadb
   # atau jika menggunakan MySQL:
   sudo systemctl start mysql
   ```
3. Buat database baru:
   ```bash
   mysql -u root -e "CREATE DATABASE IF NOT EXISTS repair_workshop;"
   ```

</details>

### Langkah 3: Setup dan Jalankan Backend - API Server

<details>
<summary><h4>🪟 Windows - Command Prompt / PowerShell</h4></summary>

1. Buka **Command Prompt** atau **PowerShell**, lalu masuk ke folder backend:
   ```cmd
   cd backend
   ```

2. Install semua dependency (library yang dibutuhkan):
   ```cmd
   npm install
   ```
   > Tunggu proses ini selesai. Akan muncul folder `node_modules` di dalam folder `backend`.

3. Buat file konfigurasi `.env`. Ketik perintah berikut **satu per satu**:
   ```cmd
   echo DATABASE_URL="mysql://root:@localhost:3306/repair_workshop" > .env
   echo JWT_SECRET="repair-workshop-secret-key-2026" >> .env
   echo JWT_EXPIRES_IN="7d" >> .env
   echo PORT=5001 >> .env
   ```
   > **Catatan:** Jika MySQL kamu memiliki password, ganti bagian `root:@` menjadi `root:PASSWORD_KAMU@`.

4. Sinkronkan struktur database (membuat tabel-tabel otomatis):
   ```cmd
   npx prisma db push
   ```

5. Masukkan data awal (data dummy untuk testing):
   ```cmd
   node seed.js
   ```
   > Jika berhasil, akan muncul pesan: `Seeding data realistis berhasil diselesaikan! 🚀`

6. Jalankan backend server:
   ```cmd
   npm run dev
   ```
   > Backend akan berjalan di **http://localhost:5001**. **Jangan tutup terminal ini!**

</details>

<details>
<summary><h4>🐧 Linux</h4></summary>

1. Buka Terminal, masuk ke folder backend:
   ```bash
   cd backend
   ```

2. Install semua dependency:
   ```bash
   npm install
   ```

3. Buat file konfigurasi `.env`:
   ```bash
   cat > .env << 'EOF'
   DATABASE_URL="mysql://root:@localhost:3306/repair_workshop"
   JWT_SECRET="repair-workshop-secret-key-2026"
   JWT_EXPIRES_IN="7d"
   PORT=5001
   EOF
   ```
   > **Catatan:** Jika MySQL kamu memiliki password, ganti bagian `root:@` menjadi `root:PASSWORD_KAMU@`.

4. Sinkronkan struktur database:
   ```bash
   npx prisma db push
   ```

5. Masukkan data awal:
   ```bash
   node seed.js
   ```

6. Jalankan backend server:
   ```bash
   npm run dev
   ```
   > Backend akan berjalan di **http://localhost:5001**. **Jangan tutup terminal ini!**

</details>

### ⚡ Jalankan Sekaligus (Satu Perintah / One-Click Run)

Anda dapat menjalankan backend dan frontend secara bersamaan hanya dengan menjalankan satu script:

**Linux / macOS:**
```bash
./run.sh
# atau:
bash run.sh

**Cross-Platform (Windows / Linux / macOS):**

node run.js
```

- Menjalankan backend di `http://localhost:5001`
- Menjalankan frontend di `http://localhost:3000`
- Menghentikan kedua server dengan bersih saat menekan `Ctrl+C`
